# Independent kit semantics review

Primary source: `swgoh-utils/gamedata`, pinned commit `8d86d7002e8cab5839f04540d93ac303db078517`, game version `0.40.6:Oq-TxiewST69Ow5E1gLW3g`. Source effects are cached in `data/gameData-cache/effect.json`; localized descriptions and ability graphs are cached alongside them. This is a focused semantic review and independent arithmetic check, not certification that every character's entire kit is supported.

The independent regression script is `scripts/testKitSemanticReview.mjs`. Unlike raw/preprocessed parity, its expectations are fixed coefficients read from source and worked-out damage/recovery/action counts. Isolation deliberately disables unrelated operations, R2 Number Crunch, opponent armor/evasion/critical avoidance, and opponent debuff uptime. This separates primitive correctness from unresolved kit interactions. High confidence still requires all active branches and dependencies to be checked.

## Implemented reusable corrections

Immunity is matched against exact positive source descriptive tags: `speed_recovery` maps to bonus TM gain immunity, `delay` to TM removal immunity, and `health_recovery` to normal recovery immunity. Unsupported filters remain explicit omissions. The compiler carries the affected operation's matching keys, so type names alone do not imply that every recovery or revival is blocked. `UNRESISTABLE` and unavoidable apply type describe landing/evasion; neither is evidence of immunity bypass. The pinned source parameter inventory contains no general immunity-bypass parameter. `NO_HEALTH_STEAL` is checked on each damage operation.

Regular and bonus-basic TM use the same immunity factor. Explicit positive/negative extra TM assumptions also respect their corresponding immunity. Normal Health recovery and direct basic recovery use the source filter, while damage Health Steal remains separate. Source-explicit 150% steal is lower-bounded at zero without a 100% cap.

Bonus basic recovery now executes once per actual bonus attack, applies assist multiplicity, source chance/recipient chance and direct context gates, and credits the affected recipients. Eligible Health Steal is credited to the basic attacker. Counter recovery runs before any member's metrics are finalized. Ordered triggers, recursively chained attacks, and timed/conditional basic effects remain outside this direct bonus-basic subset.

Recovery review found a separate arithmetic defect in `CONTEXT_MAX_MULTIPLIER`: contextual percentages were added as absolute Health/Protection points instead of multiplying the affected recipient pool. The compiler now preserves the exact source flag on recovery/shield operations, and both normal and bonus-basic paths multiply that context term by the basis pool. Explicit caster Health queries without this flag remain absolute context terms, as verified by Luminara. At source revision `53774e47015375b7`, this applies to 29 compiled recovery effects across 23 characters. Source arithmetic is shared, but each effect's conditional/event coverage still governs confidence.

The complete pinned effect table contains zero type-2 `RECOVER` or type-10 `DISTRIBUTE_RECOVERY` operations using `MAX_HEALTH`/`MAX_SHIELD`. Those parameters occur on type-18 shields. Ordinary `HEALTH`/`SHIELD` recovery uses recipient pools; caster-based healing is represented by explicit stat queries. The removed `fromCaster` inference was therefore dormant for the current recovery table. Protection Up remains the separately declared bounded temporary Protection capacity; ordinary Protection recovery remains a rate, and the asymmetric Yoda test verifies this distinction.

## Damage-result provenance review

Malak's final `specialability_darthmalak02` source reference list contains normal target damage at index 0, percent-Health-resistant target damage at index 1, raid boss damage at index 2, then `recover_health_context_self_INSTANT` with explicit `contextIndex: [0, 1, 2]`. The recovery effect is type-2 `RECOVER`, `HEALTH`, multiplier 0, context multiplier 1. Its input is the sum of the earlier selected damage results, rather than a stat query or Malak's own Health. The damage effects declare `NO_HEALTH_STEAL`; this separately declared recovery is nevertheless legal. Their target selectors determine which results exist.

`scripts/testDamageRecoverySource.mjs` checks these exact indices/effect IDs and rejects inferring a regular-basic damage result for a bonus basic. `scripts/lib/damageRecoverySource.mjs` compiles a narrow source link for earlier direct damage references in one active special. Both engines now store already-landed damage rate divided by source ability-use rate, followed by recovery effect use rate. This preserves hit/chance/mitigation factors exactly once. A source branch selecting no target contributes zero; an absent or ambiguous source operation remains an explicit missing result. Integrated tests check normal/resistant/raid results, changed target Health, unchanged caster Health, a 50% outgoing damage modifier, true/unavoidable defense/evasion bypass, and a 50% resistant-branch probability. The last case heals 51,000/time rather than squaring its branch probabilities.

Consular's damage-linked recovery `specialability_jediknightconsular02_recover_health03` instead has no explicit local `contextIndex` and no query. Its localized kit says 30% of damage dealt, but the previous compiler accepted an empty context and evaluated zero. The compiler now exposes this as missing recovery context and does not emit the unsupported recovery. Implicit sequential context requires an additional reviewed rule; it must not be generalized from Malak's explicit three-reference provenance.

## Initial Protection-to-Health conversion and receiver identity

Nihilus's `leaderability_darthnihilus_health_handler` targets Sith allies, explicitly excluding `selftag_darthmalak`. Its event-50 `PERSISTENT_EFFECT_ADD_INSTANCE` watches `leaderability_darthnihilus01_health_handler_trigger`, which is installed once by the same leader ability. The handler's three children are `query_protection_self_INSTANT` (`QUERY_STAT`, `MAX_SHIELD`, self), `leaderability_darthnihilus_health_buff` (zero Health multiplier, context multiplier 1), and `leaderability_darthnihilus_protection_debuff` (remove-all sentinel). Here, child self refers to the affected handler recipient. Querying original leader Protection for every Sith would violate both this graph and the kit's own-pool conversion wording.

Malak's `uniqueability_darthmalak02_health_handler` has the same three-child structure with its own Health/protection effects, but installs on self at battle start. The two reviewed handler IDs compile into a dedicated once-per-evaluation conversion phase, avoiding broader guesses about source creator overrides or event-bound stat queries. `scripts/lib/poolConversionSource.mjs` validates the pinned shapes and `scripts/testPoolConversionSource.mjs` checks source marker/exclusion/self ownership.

Integrated asymmetric source tests verify Nihilus 10,000 Health plus 20,000 Protection becomes 30,000 Health, while Vader 40,000 Health plus 80,000 Protection becomes 120,000 Health; Vader never receives Nihilus's 20,000 Protection. Malak 50,000 Health plus 70,000 Protection receives his own conversion to 120,000 Health and is excluded from the leader's handler. A non-Sith recipient keeps both original pools. Warm evaluations never accumulate conversion, and switching off Nihilus's leader leaves Malak's own unique conversion enabled.

The model declares `poolConversionPolicy: own-recipient-before-kit-stat-buffs`. Each compiled conversion retains an explicit ordering omission because interactions with other kit stat changes have not been independently established. Numeric own-pool conversion is supported; full battle initialization ordering is not certified.

## Highest remaining semantic priorities

1. **Retain all ancestor query gates before using downstream effects.** Hondo Profit, Padmé installation, Mastery changes and many source chains have a context query above the emitted effect. A child's local coefficient alone does not establish its eligibility. Verify positive and skip branches with both query outcomes and retain unsupported queries as omissions.
2. **Extend checked damage-result provenance.** Malak's explicit prior-damage references are implemented and independently checked above. Consular and other implicit sequential results still need a reviewed ownership and ordering rule; missing context remains a gap.
3. **Establish initialization and packet ordering.** Nihilus/Malak recipient-owned conversion and Nihilus Sith critical prohibition are now source-checked subsets. Conversion interactions with other stat buffs and general critical-event packet incidence remain explicit gaps.
4. **Bound stacks with source limits and consume them in order.** Hondo Profit and Padmé Courage use blackboards, thresholds, acquisition and consumption. A constant buff-uptime assumption cannot certify stack-dependent guaranteed critical hits, 25%/75% TM alternatives, repeated assists or 40%-target-Health Courage damage. Source `STAT_LIMIT`, `BLACKBOARD_LIMIT`, and event ownership are necessary.
5. **Review out-of-turn context independently.** Direct basic damage/recovery/TM is now handled on assists/counters, but triggers that only occur on the actor's own turn, recursive assist chains, on-hit debuffs/buffs, and receiver-specific source conditions still need ordered event support. Do not clear all basic follow-up gaps because the arithmetic helper exists.
6. **Convert Mastery using source-defined per-character dimensions.** `specialability_glhondo01_all_pirates_gain_mastery` adds 10 Mastery. It cannot safely become arbitrary equal Offense/Health; role/stat mappings and the fixture's missing native Mastery values require explicit source metadata.
7. **Keep Ultimate Charge and summon scope honest.** Hondo source effects `basicability_glhondo_3pct_ult_charge` and `leaderability_glhondo_steal_ability_ultimate_charge` remain unresolved charge-to-ultimate timing. Summons add actors, pools, abilities, and targeting state. A fixed ultimate-use assumption is a declared approximation, not checked charge coverage.

The utility objective remains team damage rate multiplied by team effective Health. These corrections change the underlying mechanics and do not impose preferred mod sets or inflate confidence labels.
# Sith outgoing critical restriction: checked source scope

The pinned `leaderability_darthnihilus_crit_avoidance_handler` installs an enemy-side event 39 interceptor for `profession_sith`. Its two children, `leaderability_darthnihilus_attack_crit_avoidance` and `leaderability_darthnihilus_ability_crit_avoidance`, apply Physical/Special critical-negate sentinels only through event 41, the same-effect completion. The compiler recognizes this exact deterministic source structure as an outgoing restriction on allied Sith. This critical restriction includes Malak; the separate Protection conversion exclusion does not apply. Other attackers retain their critical chance against the same enemy.

Independent integrated tests use real Nihilus Special damage, Malak Physical damage, Bane's source guaranteed-critical basic, Kit Fisto's non-Sith basic, JMK's source Physical/Special Vulnerable, and Savage's source critical-trigger Offense Down. Sith cannot critically hit under normal, guaranteed, or Vulnerable conditions. The restriction applies before stat-trigger weighting. Prohibited, never-critical, and non-damaging actors contribute zero outgoing critical-event incidence.

The nonzero critical-event incidence estimate still uses an action/channel proxy. Actual per-ability damage packets, mixed critical/non-critical branches, and ordered critical events are not independently modeled; compiler gaps retain that limitation. This review checks the narrow restriction and zero cases and does not certify general critical event simulation or the whole Nihilus kit.
